# 交接文件（handover.md）與簡報大綱

handover.md 是「完整版」：給接手者日後查閱，內容可以詳盡。簡報是「講解版」：每頁一個重點，細節放講者備註並指回 handover.md 的章節。

每一個說法都要能追溯到來源：在 handover.md 中以 `path/to/file.py:行號` 或 commit hash 標註。推測的內容標「（推測）」，查不到的標「**待確認**」並收進最後的「待確認事項」——交接文件寫錯比寫不知道更傷人。

## handover.md 章節（單一 repo）

1. **一句話說明** — 這個 repo 解決什麼問題、給誰用。
2. **在整體系統中的位置** — 上游（誰呼叫它 / 資料從哪來）、下游（它呼叫誰 / 寫到哪）。多 repo 時這段最重要。
3. **技術棧** — 摘要表（分類｜技術｜一句話用途），開頭註明「每項技術的要點見 tech-catalog.md」。完整的技術目錄與要點寫在 tech-catalog.md（見 `tech-catalog.md` 寫法），這裡不重複。
4. **目錄導覽** — 精簡目錄樹，每個重要目錄一句話；標出「從這裡開始讀」的檔案。
5. **核心流程** — 先寫啟動 / 請求進入的共通流程，接著 **modules.md 中每個核心邏輯模組各一個小節**：
   - 做什麼（一段話）＋ 對外介面
   - 主要檔案表（檔案｜角色）
   - 流程步驟（附 `file:line`）與關鍵規則、門檻值、錯誤行為
   - 教學重點（設計亮點、常見踩雷、可當練習的樣本）
   - **應用場景**（有演算法 / 公式 / 訓練評估的模組必寫）：`#### 應用場景（示意）` 小節，用虛構角色與 ID 逐步走一遍，每個重要分支一個場景、公式代入示意數字，最後一句寫出場景揭露的重點
   薄轉接層模組合併成一小節，用表格列出「端點 → 轉呼叫的服務」。
6. **資料模型** — 主要資料結構 / table / schema / API 介面（endpoints、input/output）。
7. **設定與環境變數** — 名稱、用途、在哪設定、各環境差異。**只寫名稱與用途，絕不寫值**；機密說明「向誰索取 / 存在哪個 secret manager」。
8. **本機開發** — 安裝、啟動、測試指令（從 README / Makefile / package.json scripts / pyproject 抓，並註明是否實際驗證過）。
9. **建置與部署** — Docker、CI/CD、k8s/Helm、排程；部署到哪些環境、如何觸發、如何回滾。
10. **監控與維運** — log 在哪看、metrics/告警、常見故障排除（從 commit 訊息中的 fix/hotfix、README troubleshooting、程式中的錯誤處理推敲）。
11. **專案歷程** — 建立時間、重要里程碑（tag、大型 feature commit）、近期活躍度、主要貢獻者。
12. **已知問題與技術債** — TODO/FIXME、hotspot 檔案（改動頻繁 = 脆弱或核心）、缺測試的區域、過時套件、文件與程式不一致處。
13. **進行中與待辦** — 未合併分支、近期 commit 方向、使用者口頭補充的事項。
14. **交接清單** — 需移交的權限與帳號（repo、雲端、DB、監控、secret）、相關文件連結、聯絡窗口。
15. **學習路徑**（教學用）— 建議的閱讀順序（第 1 天 / 第 1 週）、可以先動手的小任務。
16. **待確認事項** — 所有標「待確認」的項目彙整，給原負責人填。

## 多 repo：總覽 + 各 repo 章節

handover.md 開頭先寫「系統總覽」：
- 整體目的、各 repo 一句話角色表（repo｜角色｜技術｜部署位置）
- repo 之間的關係：呼叫關係、共用資料、部署相依（從設定檔中的 URL/host、client 程式、共用套件名、docker-compose、README 互相提及等證據推出）
- 一條跨 repo 的端到端流程

接著每個 repo 一章（上述 1–15 精簡版），最後統一的交接清單與待確認事項。

## 簡報大綱

**預設用 `teaching-style.md` 的頁序骨架**（輕鬆導讀、架構一頁帶過、演算法講細）。以下是使用者要求「正式交接版」時才用的完整大綱（單 repo 約 15 頁 + 每個核心模組 3–5 頁）：

| # | 頁面 | 建議 type | 來源章節 |
|---|---|---|---|
| 1 | 封面 | `title` | — |
| 2 | 大綱 | `agenda` | — |
| 3 | 一句話 + 為什麼存在 | `bullets` + `callout` | 1 |
| 4 | 專案一覽數字 | `stats` | facts |
| 5 | 系統架構圖 | `diagram` | 2 |
| 6 | 用到哪些技術？ / 目錄導覽 | `table` | tech-catalog.md、4 |
| 7+ | 每個核心模組：`section` → 模組架構圖 → 流程 → 關鍵規則；演算法模組加應用場景 | `diagram` + `flow` + `table`/`code` | 5.x |
| … | 資料模型、環境變數、部署流程、歷程 | `table` / `flow` / `timeline` | 6–11 |
| … | 已知問題、交接清單、Q&A | `cards` / `closing` | 12–16 |

## 講者備註寫法

教學用簡報的價值大半在備註：每頁 3–6 句，口語化（語氣見 teaching-style.md），說明「為什麼這樣設計」「常見踩雷」「去哪個檔案看細節（`file:line`）」。不知道設計原因時寫「（設計原因待確認）」，不要編。
