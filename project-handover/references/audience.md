# 產出選擇與對象角色

每次啟動 skill 時，先讓使用者決定兩件事：**要產出哪些文件**、**文件要給誰看**。同一個 repo 給新進工程師和給主管，要講的東西差很多；先問清楚，後面的閱讀深度、頁數、用詞都跟著調整。

## 1. 怎麼問

在第 1 步用 **一次** AskUserQuestion 問完（兩題），不要分兩次打斷使用者：

```
問題 1（multiSelect: true）：這次要產出哪些文件？
  - 交接文件 handover.md        —— 完整版、可持續更新的 source of truth
  - 技術目錄 tech-catalog.md    —— 專案用到的技術、版本與要點
  - 教學簡報 .pptx              —— 16:9，含架構圖、應用場景、講者備註
  - Data Science Essentials 章節 —— 簡報內的英文方法解說（需要網路查證）

問題 2（multiSelect: false）：文件主要給哪個對象？（可選 Other 自行輸入角色）
  - 新進 / 接手工程師（建議）
  - 數據科學家 / ML 工程師
  - PM / 主管
  - 非技術同仁（業務、營運）
```

- 使用者在請求裡已經說了（例：「只要簡報」「給新來的 DS 看」「給老闆報告」），就直接採用，不要再問。
- 使用者選 Other 輸入的任何角色都接受（例：「SRE」「資安稽核」「實習生」「外部合作廠商」），依第 3 節找最接近的設定，再依角色名稱的字面意思微調；不清楚時在交付時說明你的理解。
- 這兩個選擇要寫在每份產出的開頭（例：`> 對象：數據科學家｜產出：tech-catalog.md、簡報`），並在交付時再說一次。

## 2. 產出之間的相依

| 選擇 | 一定會做的內部步驟 | 說明 |
|---|---|---|
| 任何組合 | 掃描事實（facts）、模組清單（modules.md）、深入閱讀 | 品質的基礎，不能省；這兩個檔案屬於工作檔，照樣存下 |
| 只選簡報 | 仍要做技術盤點與模組閱讀 | 講者備註改指向程式碼 `file:line`，**不要**寫「見 handover.md 第 N 節」 |
| 沒選 tech-catalog.md | 簡報的「用到哪些技術？」頁照做 | 備註不要指向 tech-catalog.md |
| 選了 Data Science Essentials 但沒選簡報 | 改成 `ds-essentials.md` 獨立文件 | 同樣英文解說＋中文「在本專案」＋References |
| 沒選 Data Science Essentials | 跳過第 5.5 步的網路查證 | tech-catalog.md 不標「DS」 |

結尾 Q & A 頁的延伸閱讀只列這次真的有產出的文件。

## 3. 角色預設

| 角色 | 重點 | 深度與篇幅 | 簡報調整 | 文件調整 |
|---|---|---|---|---|
| **新進 / 接手工程師**（預設） | 怎麼跑、從哪讀、哪裡會爆、要找誰 | 完整；`file:line` 齊全 | 照 teaching-style.md 預設骨架（約 30–40 頁） | handover.md 全章節；學習路徑與交接清單完整 |
| **數據科學家 / ML 工程師** | 資料、特徵、演算法、評估、實驗設計 | 演算法與評估最深；部署與 API 細節精簡 | 演算法與應用場景加深；Data Science Essentials 建議預設勾選；部署縮成一頁 | handover.md 的資料、訓練、評估章節加深；tech-catalog.md 的 DS 項目寫完整 |
| **PM / 主管** | 這系統解決什麼問題、成效怎麼量、風險與下一步、需要的資源 | 精簡；少程式碼，多結果與數字 | 15–20 頁：先看結果、一張圖看懂、成效指標、這套系統做對的事、下一步；不放 `code` 頁、公式只留白話 | handover.md 只留 1、2、3、11、12、13 章；技術目錄只列核心 |
| **非技術同仁（業務、營運）** | 能做什麼、不能做什麼、怎麼用、出問題找誰 | 最精簡；不出現程式碼、公式、檔案路徑 | 10–15 頁：用情境與範例說明輸入 → 輸出、限制、常見問題；技術名詞第一次出現時附白話 | 改寫成「使用說明」語氣；不產 tech-catalog.md 的細節（使用者仍勾選時只留目錄表與一句話說明） |
| **SRE / 維運**（Other 常見） | 部署、設定、監控、故障排除、回滾 | 部署與維運最深 | 架構圖＋部署流程＋故障排除 cards；演算法一頁帶過 | handover.md 7–10 章加深；列出所有外部依賴與逾時設定 |
| **資安 / 稽核**（Other 常見） | 機密處理、個資流向、權限、對外介面 | 只看與風險相關的程式碼，但要附出處 | 資料流向圖（個資經過哪些元件）、機密管理、對外端點；問題照實寫，不用作者視角的軟化措辭 | handover.md 加「資料與機密流向」一節；**絕不**寫出機密值 |

- 角色只決定「講什麼、講多深」；事實、出處、安全規則（不開機密檔、不寫機密值、不用真實個資）對所有角色都一樣。
- 「簡報者就是作者」的作者視角規則（teaching-style.md）仍然適用，除非角色是資安 / 稽核或使用者要求直白的檢討。
- 語言：預設繁體中文；Data Science Essentials 的技術解說用英文。使用者輸入的角色若暗示外籍讀者（例：「海外團隊」），問一次要不要整份改英文。
